# Практика до теми

Тема: `$ARGUMENTS` — slug теорії (`modulus` → `src/content/docs/theory/modulus.md`). Якщо не вказано — спитай.
Результат: **один файл** `src/content/docs/practice/<slug>.mdx`.

Інтерфейс, перевірка відповідей і правила складу вже є — твоя робота лише **вміст**.
Формат файлу з прикладами всіх типів — [reference.md](reference.md).
Правила складу — `RULES` у `src/lib/quiz/schema.ts` (джерело правди; `npm run check` їх перевіряє).

## Кроки

1. **Прочитай** теорію теми. Завдання — тільки з того, що в ній пояснено.
2. **Виділи правила** теми → 3–6 тегів (`id` латиницею в kebab-case → назва українською). Тег = одне правило або навичка.
3. **Сплануй** розподіл «тег × рівень × тип» за складом нижче.
4. **Напиши файл** за [reference.md](reference.md): frontmatter (`title: "Практика: …"`, `sidebar` з тією самою назвою й **тим самим `order`, що в теорії**, `quiz`) → `## Коротко про головне` (3–6 пунктів) → `<Trainer />`.
5. **Перевір відповіді обчисленням**: окремим скриптом у scratchpad (`python3` з `fractions`) перерахуй кожну числову відповідь і кожне твердження з варіантів. Помилка у відповіді — найгірше, що може бути в тренажері.
6. **`npm run check`** — схема перевіряє склад, теги, варіанти. Виправляй, доки не буде `0 errors`. Потім **`npm run build`** — він рендерить формули, ловить помилки KaTeX і перевіряє пару з теорією.
7. **Перевір у браузері** (`npm run dev` → сторінка практики): пройди завдання кожного типу (choice, match, short), подивись пояснення й результат, у світлій і темній темі.

Пункт меню й кнопка «🏋️ Практика» на сторінці теорії з'являються **автоматично** — нічого не прописуй.

## Склад

| | Кількість |
|---|---|
| Усього | 10–15 |
| ★ легкі — пряме застосування одного правила | 3–5 |
| ★★ рівень НМТ — 1–2 кроки, як у реальному тесті | 5–8 |
| ★★★ пастки — з розділу «Пастки» теорії | 2–3 |
| `match` (відповідність) | 1–2 |
| `short` (коротка відповідь) | 2–3 |
| `choice` (А–Д) | решта |

Тренажер сам показує завдання від легких до складних, перемішує їх у межах рівня і перемішує варіанти.

## Правила якості

- Кожен тег покритий хоча б одним завданням; кожне завдання — рівно один тег.
- **Неправильні варіанти = конкретні типові помилки** (0 як натуральне, $0{,}(3)$ як ірраціональне, забутий знак…), а не випадкові числа.
- `why` — 1–2 речення: розв'язок і чому інші варіанти хибні (для пасток — обов'язково). Без похвали й води.
- Заборонено два завдання одного шаблону, що відрізняються лише числами.
- Числа «гарні», як на НМТ. `short` — ціле або скінченний десятковий дріб; якщо відповідей кілька — питай суму, добуток або меншу з них.
- Варіанти не залежать від порядку: без «усі перелічені». Якщо порядок важливий (числа за зростанням) — `keepOrder: true`.
- Формули — за правилами з AGENTS.md (`\N`, `0{,}25`, `-` у формулах).
