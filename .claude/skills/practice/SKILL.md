# Практика до теми

Тема: `$ARGUMENTS` — slug папки теми (`modulus` → `content/<розділ>/modulus/index.mdx`; знайди папку пошуком). Якщо не вказано — спитай.
Результат: **один файл** `content/<розділ>/<slug>/practice.mdx` поруч з `index.mdx`.

Інтерфейс, перевірка відповідей і правила складу вже є — твоя робота лише **вміст**.
Формат файлу з прикладами всіх типів — [reference.md](reference.md).
Правила складу — `RULES` у `src/features/trainer/model/schema.ts` (значення з профілю іспиту `src/features/trainer/model/exam.ts`; збирання їх перевіряє).

## Кроки

1. **Прочитай** теорію теми (`index.mdx` і підсторінки). Завдання — тільки з того, що в ній пояснено.
2. **Виділи правила** теми → 3–6 тегів (`id` латиницею в kebab-case → назва українською). Тег = одне правило або навичка.
3. **Сплануй** розподіл «тег × рівень × тип» за складом нижче.
4. **Напиши файл** за [reference.md](reference.md): frontmatter (`title: "Практика: <назва теми з малої літери>"`, `description`, `trainer`) → `## Коротко про головне` (3–6 пунктів). Тренажер сторінка показує сама — у тексті нічого не вставляй.
5. **Перевір відповіді обчисленням**: окремим скриптом у scratchpad (`python3` з `fractions`) перерахуй кожну числову відповідь і кожне твердження з варіантів. Помилка у відповіді — найгірше, що може бути в тренажері.
6. **`npm run build`** — зупиняється з поясненням українською, якщо: порушено склад чи оформлення (схема), зламана формула (`Помилка у формулі … у тексті «…»`), варіант чи назва правила не в один рядок, незнайоме поле, рисунок не знайдено, немає блоку `trainer`. Виправляй, доки не збереться.
7. **`npm run test:e2e`** — нова практика перевіряється **автоматично**: сторінка без помилок і повне проходження всіх завдань (`e2e/content.ts` знаходить її сам). Тести дописувати не треба.
8. **Перевір у браузері** (`npm run dev` → http://localhost:3000/<розділ>/<slug>/practice): пройди завдання кожного типу (choice, match, short), прочитай пояснення й результат, у світлій і темній темі. Тести ловлять поломки, а не неточності в поясненнях — читай очима.

Пункт «Практика» в меню під темою і кнопки «Практика» / «← Теорія» з'являються **автоматично** — нічого не прописуй.

Slug теми після публікації не змінюють: від нього залежить ключ збережених результатів (`trainer:<slug>`).

## Склад

| | Кількість |
|---|---|
| Усього | 10–15 |
| ★ легкі — пряме застосування одного правила | 3–5 |
| ★★ рівень НМТ — 1–2 кроки, як у реальному тесті | 5–8 |
| ★★★ пастки — з розділу «Пастки» теорії | 2–3 |
| `match` (відповідність) | 1–2 |
| `short` (коротка відповідь) | 2–3 |
| `choice` (А–Д) | решта |

Якщо таблиця розходиться з `RULES` у коді — правильний код. Тренажер сам показує завдання від легких до складних, перемішує їх у межах рівня і перемішує варіанти.

## Правила якості

- Кожен тег покритий хоча б одним завданням; кожне завдання — рівно один тег.
- **Неправильні варіанти = конкретні типові помилки** (0 як натуральне, $0{,}(3)$ як ірраціональне, забутий знак…), а не випадкові числа.
- `why` — 1–2 речення: розв'язок і чому інші варіанти хибні (для пасток — обов'язково). Без похвали й води.
- Заборонено два завдання одного шаблону, що відрізняються лише числами.
- Числа «гарні», як на НМТ. `short` — ціле або скінченний десятковий дріб; якщо відповідей кілька — питай суму, добуток або меншу з них.
- Варіанти не залежать від порядку: без «усі перелічені», без посилань на літери інших варіантів. Якщо порядок важливий (числа за зростанням) — `keepOrder: true`.
- Формули — за правилами з AGENTS.md (`\N`, `0{,}25`, `-` у формулах).
