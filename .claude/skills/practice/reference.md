# Формат файлу тренажера

Робочий зразок: `content/numbers/number-sets/practice.mdx`. Приклад кожного типу завдання друкує `npm run rules` (він уже вставлений у [SKILL.md](SKILL.md)); нижче — каркас файлу й те, чого приклади не показують.

```mdx
---
title: "Практика: числові множини"   # «Практика: » + назва теми з малої літери (абревіатури лишай як є)
description: Одне речення — що тренуємо.
trainer:
  tags:
    classify: Визначення множини числа
  questions:
    - type: choice             # далі — поля типу, як у прикладах з `npm run rules`
      level: 1
      tag: classify
      q: Яке з чисел ірраціональне?
      options: ['$\sqrt{16}$', '$0{,}(3)$', '$\sqrt{12}$', '$-\frac34$', '$3{,}14$']
      answer: 2
      why: '$12$ не є точним квадратом, тому $\sqrt{12} \in \I$. Решта записуються дробом.'

    - type: short
      level: 2
      tag: classify
      q: |-                      # кілька абзаців чи виносна формула — блок `|-` (бекслеші в ньому не екрануються)
        Розв'яжи систему:

        $$
        \begin{cases} x + y = 5 \\ x - y = 1 \end{cases}
        $$

        У відповідь запиши добуток $x \cdot y$.
      figure: { src: ./figures/system.svg, alt: Графіки двох прямих }   # за потреби; файл у папці теми
      answer: 6
      why: 'Додаємо рівняння: $2x = 6$, $x = 3$, тоді $y = 2$; добуток $6$.'
---
```

Під frontmatter — нічого: практика це тільки тренажер, він з'являється сам, бо сторінка бачить блок `trainer`. Правила й шпаргалки належать сторінці теорії; текст у тілі `practice.mdx` зупиняє збирання. Файл лежить поруч з `index.mdx` теми, тож пункт «Практика» в меню й кнопки переходу теж автоматичні.

## Тексти (`q`, `options`, `left`, `right`, `why`, назви тегів)

- Markdown і формули — як у теорії (той самий конвеєр): `**жирний**`, `$...$`, `\N`, `0{,}25`.
- `options`, `left`, `right`, назви тегів — **один рядок**; список чи абзаци — збирання впаде з поясненням.
- `q` і `why` — можуть мати кілька абзаців, виносну формулу `$$…$$` чи таблицю: YAML-блок `|-` (приклад вище). В один рядок — звичайний рядок у лапках.
- Рисунок до умови — `figure: { src: ./figures/<ім'я>.svg, alt: <опис> }`: файл svg/png/jpg/webp у папці теми, вбудовується під час збирання; `alt` — для читачів екрана.
- **YAML-лапки:** текст з формулами або двокрапкою — завжди в одинарних лапках `'...'` (бекслеші в них не екрануються; у подвійних `\s`, `\f` — це escape-послідовності, LaTeX зламається). Апостроф усередині — типографський `’` (`від’ємні`), бо `'` закриває рядок.
- Без лапок — лише простий текст без формул. Пастки YAML без лапок:
  - `**жирне**` на початку → помилка (`*` — це посилання-аліас);
  - `: ` усередині (`Скільки чисел серед: …`) → помилка;
  - ` #` усередині (`номер #2`) → **мовчки обрізає** текст до `номер` — збирання не впаде, тож тільки лапки.
- Варіанти в `choice` і `multi` — різні; `keepOrder: true` — лише якщо порядок важливий. У `multi` правильних від 2 до «всі мінус один» — одна правильна це `choice`.
