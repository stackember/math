# Теорія теми

Тема: `$ARGUMENTS` — `<предмет>/<розділ>/<slug>` (напр. `math/numbers/fractions`) і, за потреби, шлях до матеріалу власника (файл або текст у повідомленні). Якщо чогось не вказано — спитай. Slug англійською в kebab-case, без номерів; після публікації не змінюється (ключ прогресу практики). Предмет має існувати (`content/<предмет>/meta.json`), інакше спершу skill `/subject`.
Результат: `content/<предмет>/<розділ>/<slug>/index.mdx` + slug у `pages` файлу `content/<предмет>/<розділ>/meta.json`. Нового розділу — папка з `meta.json` (`title`, `icon` з lucide, `pages`) і slug у `pages` файлу `content/<предмет>/meta.json`.

Правила запису (формули, MDX, схеми) підвантажуються з `.claude/rules/content.md`, правила предмета (програма, позначення, пастки) — з `.claude/rules/subjects/<предмет>.md`; зразок — `content/math/numbers/number-sets/index.mdx`, шаблон — [reference.md](reference.md).

## Кроки

1. **Вхідні дані.** Прочитай правила предмета, матеріал власника, сусідні теми розділу (що вже пояснено, на що можна спертися) і `content/<предмет>/<розділ>/meta.json` (місце теми в порядку вивчення). Пиши лише те, що в матеріалі й шкільній програмі: сайт не прив'язаний до підручників.
2. **План.** Випиши правила теми (3–6) — це майбутні теги практики. Для кожного — один приклад з розв'язком і одна типова помилка.
3. **Напиши файл** за [reference.md](reference.md): `title`, `description` (одне речення, що тема дає) → `## Коротко` → `## Простими словами` (лише якщо треба: звідки взялося, аналогія, алгоритм) → `## Приклади` → `## Пастки`. Без тестів і вправ — перевірка знань лише в практиці. Велику тему діли на підсторінки в тій самій папці.
4. **Перерахуй кожен приклад** окремим скриптом `python3` у scratchpad (`fractions`) перед тим, як записати.
5. **Схема чи рисунок** — лише якщо показує ідею теми (вкладеність, відстань, поділ): компонент у `src/features/diagram/*/<предмет>/` за правилами з `.claude/rules/content.md`; графіки — Mafs; геометрія — SVG у `figures/`.
6. **`npm run check`** — секунди: frontmatter, формули (усі помилки одразу), розділи теорії в правильному порядку, словник, мінус і кома поза формулами, `meta.json`. Виправляй, доки не буде «Контент у порядку».
7. **Перегляд у браузері** (`npm run dev` → http://localhost:3000/<предмет>/<розділ>/<slug>): світла й темна тема, телефон. Читай очима: тести ловлять поломки, а не неточності.
8. **Агент `math-checker`** на файл — незалежна перевірка математики. Виправ усе, що він знайшов, і запусти ще раз.
9. **`npm run verify`** — повна перевірка перед завершенням. Нова сторінка потрапляє в e2e автоматично.
10. **Підсумок власнику:** що додано, які правила виділено (кандидати в теги практики), що лишилось на його розсуд. Коміт — лише якщо попросить.

## Чек-лист якості

- Кожне правило має приклад з розв'язком; приклади важливіші за слова.
- «Пастки» — з типових помилок іспиту (див. правила предмета), у `<Callout type="warn" title="Не плутай">`.
- Коротко, без води; терміни проєкту: тема, теорія, практика, завдання, правило. Слів «урок» і «питання» немає.
- Числа «гарні», як на іспиті; відповіді перераховано.
