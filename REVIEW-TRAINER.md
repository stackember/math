# Тренажер: ревʼю і план v2

## 1. Як працює зараз

`content/practice/<slug>.mdx` → YAML `quiz` у frontmatter → Zod (`src/lib/quiz/schema.ts`: склад 10–15, рівні, типи, унікальність варіантів) → `Trainer` (сервер) рендерить кожен текст через `renderInline` (Markdown + KaTeX, рівно один абзац) → `QuizLoader` (`next/dynamic`, `ssr:false`) → `Quiz` (клієнт): `createSession` перемішує завдання в межах рівня і варіанти, `sessionReducer` веде автомат «відповідаю → перевірено → далі/результат», `storage.ts` зберігає best/last у `localStorage`.

## 2. Що добре

- Три типи завдань = формат НМТ (вибір А–Д, відповідність 3×5, коротка відповідь). Тлумачення чисел (`−2,5`, `-2.5`, `-5/2`) — правильне й протестоване.
- Reducer без React, точкові дії (`choose`, `match`, `input`) — швидкі кліки не перетирають одне одного; це зафіксовано тестом.
- Склад тренажера як правило збірки — захист від «розмитих» AI-тестів; спростовано як проблему: це задокументована продуктова вимога, а не випадкова константа.
- Повтор помилок, результат за правилами (тегами), рекорд — правильні продуктові рішення.

## 3. Проблеми (повні сценарії — REVIEW-FINDINGS.md / панель code-review)

- **Формат даних.** Один рядок на текст — не можна записати систему рівнянь, таблицю, умову з абзаців, рисунок; `$$…$$` в один рядок мовчки стає inline, GFM-таблиця — сирим текстом (F5). YAML у звичайних лапках вимагає п'яти обхідних правил; ` #` мовчки обрізає текст (F41). Нестрогі об'єкти ковтають помилки в назвах полів (F11).
- **Схема.** Дублікати `left/right` не ловляться (F2); половина помилок збірки — англійською (F4); пояснення id тегу ховається (F12); `POSITIONAL` ловить два формулювання (F13); `in` проти `Object.prototype` (F14); `short.answer` не перевіряється на скінченний дріб.
- **Движок.** `checked` дублює `results.length > index` (F44); `Draft` і `Question` — паралельні union-и з мовчазними fallthrough (F43); порядок рядків результату випадковий (F15); вердикт і текст правильної відповіді живуть у view.
- **UI і доступність.** Глобальний Enter (F1), автоповтор (F7), модифікатори (F8); `role=radio` без клавіатурної моделі (F26); `aria-pressed`, що не перемикається (F25); втрата фокусу і відсутність озвучення результату (F27).
- **Збереження.** Будь-який JSON приймається без перевірки — валить сторінку (F9); ключ похідний від URL; немає версії формату.
- **Тести.** Правильність оцінювання при перемішуванні не перевіряється (F28); повтор помилок — ні (F31); локатор e2e візьме будь-яку таблицю на сторінці (F29); layout міряється до монтування (F32); мобільний проєкт не ганяє тренажер (F34).

## 4. Формат даних v2

Лишити YAML у frontmatter `practice.mdx` (один файл, Zod, Fumadocs), змінити правила запису:

```mdx
---
title: "Практика: числові множини"
description: 13 завдань у форматі НМТ на числові множини N, Z, Q, I, R.
trainer:
  tags:
    sets: Що входить у кожну множину
    symbols: >-
      Значки $\in$, $\notin$, $\subset$, $\cup$
  questions:
    - type: choice
      level: 1
      tag: sets
      q: >-
        Яке з чисел є натуральним?
      options: ["$0$", "$-3$", "$7$", '$\frac12$', '$\sqrt2$']
      answer: 2
      why: >-
        Натуральні — це $1, 2, 3, \dots$ Число $0$ і від'ємні числа не натуральні,
        $\frac12$ — не ціле, $\sqrt2$ — ірраціональне.

    - type: short
      level: 2
      tag: classify
      q: |
        Розв'яжіть систему і знайдіть $x + y$:

        $$
        \begin{cases} x + y = 5 \\ x - y = 1 \end{cases}
        $$
      figure: figures/system.svg # за потреби; шлях відносно папки теми
      answer: 5
      why: >-
        Додаємо рівняння: $2x = 6$, $x = 3$, $y = 2$.
---

## Коротко про головне

- …
```

| Поле                       | Правило                                                                                                                     |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `q`, `why`, назви тегів    | блоковий скаляр `>-` (один абзац) або `\|` (кілька абзаців, `$$`, таблиця GFM, список); рендер як блоковий Markdown         |
| `options`, `left`, `right` | flow-масив у одинарних лапках (блокові скаляри в `[…]` неможливі); рівно один абзац — перевірка на mdast                    |
| `answer` (short)           | число зі скінченним десятковим записом (≤ 4 знаки) — перевірка схемою; опційно `answers: [a, b]` для структурованих завдань |
| `figure`                   | SVG/PNG поруч із темою; на сервері вбудовується як `<img>` з `alt` із поля `figureAlt`                                      |
| `keepOrder`                | як зараз; об'єкти `strictObject` — помилка в назві поля зупиняє збірку                                                      |
| повідомлення               | кожне вбудоване правило Zod — з українським `error`; `z.config(z.locales.uk())` як запасний переклад                        |

Чому не TypeScript-модулі замість YAML: типізація й багаторядковість спокусливі, але YAML уже валідується Fumadocs під час збірки з точним шляхом, лишається «даними», а блокові скаляри знімають усі відомі болі. Повертатися до цього питання лише якщо з'являться параметризовані завдання (генерація чисел під час проходження).

## 5. Движок v2

- `Step` як дискримінований union `{ type: "choice"; question; order; draft: number | null } | { type: "match"; …; draft: (number|null)[] } | { type: "short"; …; draft: string }` — один `switch` замість подвійних guard-ів; додати четвертий тип = помилки компіляції в усіх потрібних місцях.
- `isChecked(s) = s.results.length > s.index` замість поля `checked`.
- У движок із view: `verdict(share, mode)`, `answerText(step)` (літера відносно `order`), `stars(level)`, `LEVELS = { label, variant }` — усе в модулях без zod (щоб клієнт не тягнув схему).
- `tagStats` → порядок `Object.keys(tags)`.
- Збереження:
  ```ts
  const progressSchema = z.object({
    version: z.literal(2),
    best: scoreSchema.optional(), last: scoreSchema.optional(),
    tags: z.record(z.string(), z.object({ correct: z.number(), total: z.number() })).optional(),
  })
  ```
  невалідне → `{}`; ключ `trainer:<slug теми>`; запис результату — у reducer-дії `finish` (ефект збереження в одному місці, тест на «повтор не змінює рекорд»).
- `createSession([])` → явна помилка замість `steps[0].question` на порожньому масиві.

## 7. Перевірки й тести

- Схема: `strictObject`, унікальність `options/left/right`, `Object.hasOwn`, скінченний дріб для `short`, українські повідомлення з тестом на точний текст, `POSITIONAL` розширити (усе/все, із, посилання на літери) — як запобіжник.
- `renderTrainer`: блоковий конвеєр (`remarkGfm` із `fumadocs-core/mdx-plugins`) для `q/why/tags`; inline-перевірка на mdast для варіантів; усі помилки KaTeX одним списком.
- Unit: `storage.test.ts`, `verdict.test.ts`, `answerText`, reducer `finish`/retry.
- E2E: прохід із правильними відповідями з frontmatter → «Правильно» щоразу і `N/N`; прохід з помилками → літера у «Відповідь: X)» відповідає DOM; «Повторити помилки (N)» → N завдань, рекорд не змінюється; локатори в межах картки; мобільний проєкт з тренажером і схемою; `axe` без порушень.

## 8. Майбутнє (не робити зараз, але не заважати)

- **Рисунки:** поле `figure` + SVG у папці теми; графіки функцій — компонент Mafs, доступний у MDX і як `figure: component:…` у завданні.
- **Дві відповіді** у `short` (`answers: [a, b]`) — структуровані завдання НМТ.
- **Змішаний тест:** сторінка, що збирає завдання з кількох `practice.mdx` за складом НМТ; движок уже працює зі списком завдань.
- **Прогрес:** сторінка «Тренажери» з best/last і слабкими правилами з усіх `trainer:*` ключів.
- **Інтервальне повторення:** на основі `tags` у сховищі — після прогресу.
