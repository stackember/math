## Вердикт

- **База гарна.** Стек актуальний (усі залежності — останні стабільні), логіка тренажера відділена від React (чистий reducer + функції з тестами), перевірки під час збірки з українськими поясненнями, автоматичні e2e для нового контенту. Математика в контенті перерахована — помилок немає.
- **51 підтверджена проблема, 0 критичних, 7 середніх.** Головні: глобальний обробник Enter перехоплює клавішу з пошуку й меню; схема не ловить однакові пункти у відповідності; модель `theory/<slug> ↔ practice/<slug>` ламається на вкладених темах, а перевірка «практика без теорії» зараз узагалі не спрацьовує; половина помилок збірки — англійською; тексти завдань обмежені одним рядком (без систем рівнянь, таблиць, рисунків); e2e не перевіряє, що правильна відповідь зараховується. Повний список — `REVIEW-FINDINGS.md` і панель code-review.
- **Головне архітектурне рішення:** перейти на **співрозташування теми** — `content/<розділ>/<тема>/index.mdx` (теорія) + `practice.mdx` (практика). Це прибирає ~80 рядків евристик (`topics.ts`) разом із 5 знахідками, робить «додати тему» = «створити одну папку» і дає розділи для 40+ тем програми НМТ. Деталі — `REVIEW-ARCHITECTURE.md`.
- **Тренажер:** формат даних лишити (YAML у frontmatter, перевірка Zod), але: блокові скаляри, блоковий Markdown для умови й пояснення, `strict`-схема з українськими повідомленнями, рисунки, стабільний ключ прогресу, бібліотечний `RadioGroup` замість власних `role=radio`. Деталі — `REVIEW-TRAINER.md`.
- **Підтримка через Claude Code:** короткий CLAUDE.md + правила за шляхами, три skills (`/theory`, `/practice`, `/review-topic`), агент-перевіряльник математики, швидкий `npm run check` (< 10 с) замість повної збірки в циклі правок, hooks для форматування і перевірки контенту, allowlist дозволів, CI. Деталі — `REVIEW-AI-WORKFLOW.md`.

## Ідея проєкту і що її підсилить

Ідея сильна і правильно обмежена: тема = теорія + практика у форматі НМТ, прогрес у браузері, без зайвих сервісів. Що додати (у порядку користі, без ускладнення додавання контенту):

1. **Сторінка прогресу** («Тренажери»): усі практики, найкращий/останній результат, слабкі правила (теги з помилками) — лише клієнтський компонент над `localStorage` і список практик зі `source`.
2. **Збережені результати за правилами** (теги), а не лише рахунок — основа для «повторити слабкі місця» і прогресу.
3. **Рисунки й графіки** як частина завдання (`figure` у завданні; SVG-файл поруч із темою або компонент Mafs) — без цього геометрія і функції не зайдуть.
4. **Змішаний тест у форматі НМТ** (22 завдання з різних тем, таймер) — движок уже приймає будь-який список завдань; потрібна лише сторінка-збирач. Робити після 10+ практик.
5. **Структуровані завдання з двома відповідями** (у НМТ частина завдань з короткою відповіддю має дві відповіді) — поле `answers: [a, b]` у типі `short`. Перевірити актуальний формат НМТ перед реалізацією.
